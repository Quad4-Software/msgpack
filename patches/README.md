# Upstream-portable patches

This folder ships the security, correctness, and performance fixes
from this fork as standalone, individually-reviewable `.patch` files
generated against the original [vmihailenco/msgpack v5.4.1] tree.

Every patch is:

- **Self-contained.** One topic, one file touched, one purpose.
- **Wire-format compatible.** No on-disk encoding changes.
- **API compatible.** No exported function signatures change.
- **Unconditional.** Applies cleanly with `patch -p1` from the package
  root of an unmodified upstream checkout (the directory that contains
  `decode.go`, `encode.go`, etc.).

The intended audience is downstream forks (including the upstream
`github.com/vmihailenco/msgpack/v5` repository itself) that want to
adopt one or more of the fixes without taking on the rest of this
fork's housekeeping (module path move into `pkg/msgpack/`, CI
configuration, dependency rewrites, etc.).

## Patches

| File | Topic | Severity |
| ---- | ----- | -------- |
| `0001-decoder-clamp-slice-allocation.patch` | Clamp `decodeSlice` initial capacity; fix `decodeSliceValue` flag bit comparison. | High (DoS / OOM via forged `array32` length, plus a bug that disabled the existing limit on the reflective slice path). |
| `0002-decoder-clamp-bytes-and-string-allocation.patch` | Route `Decoder.bytes` and `Decoder.bytesPtr` through the cap-bounded `readNGrow`. | High (DoS / OOM via forged `bin32` / `str32` length). |
| `0003-decoder-clamp-map-allocation.patch` | Clamp `DecodeMap` and `DecodeUntypedMap` initial sizing hint. | High (DoS / OOM via forged `map32` length). |
| `0004-decoder-accept-float-into-int.patch` | Accept finite, integer-valued `float32` / `float64` codes in `Decoder.int` and `Decoder.uint`. | Medium (correctness; fixes the JSON-then-msgpack pipeline panic). |
| `0005-decoder-fix-preallocator-goroutine-leak.patch` | Replace the perpetual per-type goroutine + buffered channel in the `UsePreallocateValues` path with a `sync.Map` of `*sync.Pool`. | High (goroutine and memory leak in long-running services). |
| `0006-encoder-zero-alloc-byte-writer-and-pregrow-marshal.patch` | Per-`byteWriter` scratch buffer to make `WriteByte` zero-alloc; pre-grow the `Marshal` `bytes.Buffer` to skip the first doublings. | Performance (fewer allocations per `Marshal`). |
| `0007-decoder-pool-bytes-reader-in-unmarshal.patch` | Add a `sync.Pool` of `*bytes.Reader` so `Unmarshal` no longer allocates one per call. | Performance (fewer allocations per `Unmarshal`). |

The numeric ordering reflects the suggested merge order: security and
correctness fixes first, performance last. The patches are
independent and can be cherry-picked individually in any order.

## How to apply

From a clean checkout of upstream `vmihailenco/msgpack/v5` (or any
fork that still has the files at the package root):

```
cd path/to/msgpack
for p in /path/to/this/folder/*.patch; do
    patch -p1 < "$p"
done
```

To apply only a subset, replace the loop with the specific filenames
you want.

If your fork has moved the files into a subdirectory (this fork keeps
them under `pkg/msgpack/`), apply with `--directory`:

```
patch -p1 --directory=pkg/msgpack < 0001-decoder-clamp-slice-allocation.patch
```

The patches are also valid `git` patches and can be applied with
`git apply` or, after re-headering with a `From:`/`Date:` line, with
`git am`. They are intentionally generated without the `git diff`
extended headers so they apply equally cleanly with plain `patch(1)`.

## Verifying

After applying, the package should still build, vet, and test:

```
go build ./...
go vet  ./...
go test ./...
```

Each patch was generated by extracting the corresponding file from
the upstream `v5.4.1` tag, applying the surgical change, and running
`diff -u` against the original. The resulting tree round-trips
byte-for-byte against the reference patched tree used in this
fork's own test suite.

## Provenance

The base tree used to generate these patches is the merge commit
`19c91dfdfa062658c39d9321be26163fc5833bd1` (release of `v5.4.1`) of
`github.com/vmihailenco/msgpack/v5`. None of the patches depend on
any code that this fork added on top of that tree (no new helpers,
no renamed functions, no changed import paths). Every helper they
reference (`readNGrow`, `sliceAllocLimit`, `bytesAllocLimit`,
`maxMapSize`, `disableAllocLimitFlag`, `usePreallocateValues`) is
already present at `v5.4.1`.
